scaLineage
Custom built SAS macro programs to trigger recording and extracting information about input, output, and the use of macro symbols from a SAS program while it is running. The captured information can provide a simple static data lineage diagram. As a minimum, Base SAS Software, version 9.4 Maintenance 4 installation is required to run these macros.

Detailed Description

Needs the tables generated by 

- %lin_readLog
- %lin_prepSource
- %lin_exprDataStep
- %lin_exprSql
- %lin_tokenize

SCAPROC records which columns every step read and wrote (ATTR records). Those facts are combined with the derivations found in the step source, so every column written by a step gets one or more edges back to the column(s) it came from:

From Description
EXPR derived by an expression (assignment / select item); EXPR holds the text
RENAME renamed (rename= option or RENAME statement)
NAME same column name in an input of the step (pass-through; also the only information available for steps generated by a macro, which have no recorded source)
FILE read from an external file (PROC IMPORT, INFILE, ...)
INPUT read by an INPUT statement from an INFILE or in-stream data
CONST expression without any column (constant, COUNT(*), ...)
AUTO automatic column of PROC SUMMARY / MEANS (FREQ, TYPE)
NOSOURCE the step has no recorded source (code that was included or generated by a macro that was itself included, CALL EXECUTE, ...) and the column name is in no input, so nothing can be said
UNRESOLVED the step has source, but nothing in it says where the column came from

A data set that is written more than once gets a version number (1, 2, ...), so a step that reads and rewrites the same table (PROC SORT, PROC APPEND, ...) does not create a cycle. Version 0 is a data set that was only read (it already existed).

Creates

  • work.&p_prefix._collin: Column level lineage for each step

    variable Description
    step The step number of the DATA step
    procname The name of the procedure
    method The method used by the procedure
    fromKind The kind of the source
    (data set (ds), file, inline, none)
    fromDs The source data set
    fromVer The version of the source data set
    fromVar The source variable
    toDs The target data set
    toVer The version of the target data set
    toVar The target variable
    expr The expression that defines the target variable

  • work.&p_prefix._dsver: Dataset version information for each step
    variable Description
    step The step number of the DATA step
    io(IN|OUT) The role of the data set (input or output)
    ds The data set
    ver The version of the data set

Example usage: 

%lin_buildLineage(p_prefix=&p_prefix
, p_stepsDsName=work.&p_prefix._steps
, p_dsioDsName=work.&p_prefix._dsio
, p_fileioDsName=work.&p_prefix._fileio
, p_attrsDsName=work.&p_prefix._attrs
, p_stmtsDsName=work.&p_prefix._stmts
, p_aliasDsName=work.&p_prefix._alias
, p_eexprDsName=work.&p_prefix._eexpr
, p_refDsName=work.&p_prefix._ref)
Parameters
[in]p_prefix=Prefix of the WORK tables. Default:lin.
[in]p_stepsDsName=Stepinformation for each step. Default: work.&p_prefix._steps
[in]p_dsioDsName=Datasetinput/output information for each step. Default: work.&p_prefix._dsio
[in]p_fileioDsName=Fileinput/output information for each step. Default: work.&p_prefix._fileio
[in]p_attrsDsName=Attributeinformation for each step. Default: work.&p_prefix._attrs
[in]p_stmtsDsName=Sourcecode for each step. Default: work.&p_prefix._stmts
[in]p_aliasDsName=ConcatenatedLibrary alias information. Default: work.&p_prefix._alias
[in]p_eexprDsName=Expressioninformation for each DATA step. Default: work.&p_prefix._eexpr
[in]p_refDsName=Columnreferences for each expression. Default: work.&p_prefix._ref
